# Deploying to GitHub + Render

## 1. Create the GitHub repository and push

```bash
cd busyatra
git init -b main           # skip if already a repo
git add .
git commit -m "BusYatra bus booking platform"
# create an empty repo on github.com (no README), then:
git remote add origin https://github.com/<you>/busyatra.git
git push -u origin main
```

`.env` files are git-ignored; only `.env.example` files are committed. Double-check with `git status` before the first push.

## 2–9. Render (Blueprint, recommended)

The repo has a [`render.yaml`](../render.yaml) that creates everything:

| Resource | Type | Notes |
| --- | --- | --- |
| `busyatra-db` | PostgreSQL | `DATABASE_URL` is wired into the API automatically |
| `busyatra-api` | Web service (Node), root `backend/` | start runs `prisma migrate deploy` + idempotent seed, then the server |
| `busyatra-web` | Static site, root `frontend/` | SPA rewrite `/* → /index.html` |

1. Render dashboard → **New + → Blueprint** → connect the GitHub repo → **Apply**.
2. Render prompts for the `sync: false` variables. Minimum to get running:
   - `busyatra-api` → `FRONTEND_URL` = the static site URL, e.g. `https://busyatra-web.onrender.com`, and `SEED_ADMIN_PASSWORD`.
   - `busyatra-web` → `VITE_API_URL` = the API URL, e.g. `https://busyatra-api.onrender.com`.
   Leave SMTP / Salesforce / Agentforce empty for now — the app runs with dev-log email and the mock agent.
3. `JWT_SECRET` and `AGENT_ACTION_API_KEY` are generated by Render. Copy `AGENT_ACTION_API_KEY` for the Salesforce Named Credential later.
4. Wait for the deploys. Check `https://<api>/api/health`.
5. Because the frontend URL is only known after the first deploy, set `FRONTEND_URL` / `VITE_API_URL` and **redeploy both services** (Vite bakes `VITE_API_URL` into the build).

**Migrations & seed** run on every API start (`npm run start:render`). Both are idempotent: the catalogue is created once, schedules are topped up to 30 days ahead (a background job also does this every 6 hours). To run manually: Render → `busyatra-api` → **Shell** → `npx prisma migrate deploy && npm run seed`.

Free-tier notes: free web services sleep when idle (first request takes ~1 min), and free Postgres databases expire after a limited period — use a paid plan for anything beyond a demo. Background jobs run in-process; for multiple instances move them to a Render Cron Job.

### Manual setup (without the Blueprint)

- **Database**: New → PostgreSQL. Copy the *Internal Database URL*.
- **API**: New → Web Service → repo, Root Directory `backend`, Build `npm ci && npx prisma generate`, Start `npm run start:render`, env vars from `backend/.env.example` (`NODE_ENV=production`, `DATABASE_URL`, `JWT_SECRET`, `FRONTEND_URL`, …). Health check path `/api/health`.
- **Frontend**: New → Static Site → Root `frontend`, Build `npm ci && npm run build`, Publish `dist`, env `VITE_API_URL`, and add a Rewrite rule `/*` → `/index.html`.

## 10. SMTP

Any SMTP provider works (Brevo, Mailgun, SendGrid, Amazon SES, Gmail with an app password). Set on the API:

```
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=<login>
SMTP_PASS=<smtp key>
SMTP_FROM="BusYatra <tickets@yourdomain.com>"
```

Port 465 uses implicit TLS automatically. The sender address must be verified with your provider. Failed sends are retried with exponential backoff (up to 5 attempts); status is visible on the ticket page and in the database (`EmailNotification`).

## 11. Salesforce

Follow [SALESFORCE_SETUP.md](SALESFORCE_SETUP.md), then add the `SALESFORCE_*` variables to `busyatra-api` and redeploy.

## 12. Agentforce

Follow [AGENTFORCE_SETUP.md](AGENTFORCE_SETUP.md). The Named Credential URL is your Render API URL; set `AGENTFORCE_CONFIGURATION` on `busyatra-api` and redeploy.
